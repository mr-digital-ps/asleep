## 1. Оптимизация производительности Graph View при приближении (FPS Drop при зуме)

### Симптом
* При отдалении (`zoomScale <= 0.60`) текстовые метки узлов скрываются, и граф работает на максимальном FPS (60–120+ к/с).
* При приближении (`zoomScale > 0.60`) включается отрисовка текста для всех 100+ узлов, и производительность резко падает («еле дышит»).

### Почему SQLite здесь не поможет
* SQLite — это дисковая база данных. Данные графа уже загружены в оперативную память. Чтение с диска на каждый кадр только добавило бы задержек (I/O overhead).
* Реальное «бутылочное горлышко» находится внутри графического конвейера **Qt Quick Canvas 2D (`graph_renderer.js`)**:
  1. **Бесконечный `wrapGraphText` на каждый кадр:** Для каждого узла 60 раз в секунду вызывается `ctx.measureText()` на каждое слово заголовка.
  2. **Отсутствие Viewport Frustum Culling (отсечения невидимого):** Когда камера приближена, на экране видно лишь 10–15 узлов. Однако рендерер честно форматирует и рисует текст для всех 100+ узлов далеко за пределами экрана.
  3. **Тяжёлая растеризация шрифтов в 2D Canvas:** `ctx.fillText()` в QML Canvas выполняется на CPU.

### Будущее решение (Без усложнения архитектуры)
1. **Frustum Culling (Отсечение за экраном):** Рисовать текст только если экранные координаты узла попадают в границы видимого окна:
   ```js
   var sx = n.x * zoom + panX, sy = n.y * zoom + panY;
   if (sx < -100 || sx > viewWidth + 100 || sy < -100 || sy > viewHeight + 100) return;
   ```
2. **Кэширование переносов строк (Pre-wrapped Labels):** Рассчитывать разбиение текста на строки один раз при загрузке графа, а не каждый кадр.
3. **Растровые спрайты / Текстурный атлас:** При необходимости кэшировать отрисованный текст узла в оффскрин-картинку (битмап).

## 2. Интерактивный верстак Metro (Draggable Transit Map)

### Концепция
Возможность для пользователя вручную двигать элементы схемы метро сюжета, чтобы наводить идеальную визуальную эстетику и распутывать сложные пересечения.

### Архитектурные мысли и механика
* **Свобода по $Y$ (Высота):** Полная свобода перемещения станций по вертикали. Входящие и исходящие рельсы (Безье / 45-градусные фаски) растягиваются и сгибаются в реальном времени вслед за курсором.
* **Защита оси $X$ (Стрела времени):** Ограничение движения по горизонтали — станция не должна перелетать соседние эпохи, чтобы сохранялась монотонность времени и каузальность событий.
* **Перестановка полос (Lane Swapping):** Возможность менять вертикальный порядок линий на станции пересадки (например, поднять ветку Габсбургов выше Франции).
* **Хранение в `.asleep/`:** Сохранять пользовательские смещения станций ($\Delta y$) и приоритеты полос в локальный кэш проекта (`metro_positions.json` или таблицу SQLite), чтобы правки сохранялись между перезапусками.
* **Ограничение (KISS):** Не превращать схему в неконтролируемый свободный Canvas, чтобы не ломать строгую окталинейную эстетику (0°, 45°, 90°) Гарри Бека.

## 3. Развитие канонического диалекта `asleep-flow` (`.af`)

* Закрепление расширения `.af` как нативного формата для хронологических карт и структурированных сюжетных заметок.
* Поддержка сквозных магистралей (26 канонических линий) и локальных актеров сцены.
* Межстраничная навигация через трансклюзии и ссылки следующей эпохи `-> [[Имя эпохи]]`.
