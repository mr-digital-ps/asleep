# Урок 3: Магия Сигналов PyQt против React

Сигналы и Слоты (`pyqtSignal`) — это, пожалуй, самое мощное архитектурное решение во всем фреймворке Qt. Понимание этой концепции делает разработку десктопных приложений невероятно приятной.

Давайте сравним подход PyQt с тем, как мы привыкли решать проблемы в React.

## Проблема: Prop Drilling (Прокидывание пропсов)
Представьте структуру компонентов: 
`MainApp` -> `MainLayout` -> `InputLayout` -> `CalcButton`.
Кнопка находится на 4-м уровне вложенности. При нажатии на кнопку нам нужно обновить стейт (память), который лежит на самом верху в `MainApp`.

### Как это решается в базовом React?
Вам приходится прокидывать функцию изменения стейта (callback) через все слои сверху вниз:
```javascript
// React: Родитель передает функцию ребенку
function MainApp() {
  const [memory, setMemory] = useState([]);
  
  // Прокидываем вниз... и еще раз вниз...
  return <MainLayout onButtonClick={(text) => setMemory([...memory, text])} />
}

function CalcButton({ text, onButtonClick }) {
  // Если родитель забыл передать onButtonClick, приложение упадет с ошибкой!
  return <button onClick={() => onButtonClick(text)}>{text}</button>
}
```
**Минус React:** Дочерний компонент жестко зависит от родителя. Он *ожидает*, что ему передадут функцию. Если не передадут — будет ошибка.

---

### Как это решается в PyQt? (Кастомные Сигналы)
В PyQt мы используем концепцию **"Переворот контроля" (Inversion of Control) через Event Emitter**. 

Ребенок НЕ ждет ничего от родителя. Ребенок сам создает "радиостанцию" (Сигнал) и просто вещает в эфир, когда что-то происходит.

```python
class InputLayout(QGridLayout):
    # 1. Ребенок создает свою радиостанцию (Сигнал), которая передает строку
    button_pressed = pyqtSignal(str)

    def __init__(self):
        # ...
        btn = QPushButton("5")
        # 2. Ребенок просто вещает в эфир. Ему ПЛЕВАТЬ, слушает ли кто-то радио.
        btn.clicked.connect(lambda: self.button_pressed.emit("5"))
```

Родитель (`MainApp`), когда создает ребенка, настраивает свой "приемник" на волну этого ребенка:
```python
class MainApp(QWidget):
    def __init__(self):
        self.input_layout = InputLayout()
        
        # 3. Родитель "подписывается" на радиостанцию ребенка
        self.input_layout.button_pressed.connect(self.handle_input)
```

### Почему подход PyQt такой крутой?
1. **Нулевая зависимость (Decoupling):** Вы можете взять класс `InputLayout`, вырезать его из калькулятора и вставить в проект интернет-магазина. Он будет продолжать излучать сигнал `button_pressed`, даже если в новом приложении никто не подключил к нему `connect()`. Код **не упадет** с ошибкой (в отличие от React, где вызов `undefined` пропса уронит сайт).
2. **Никакого Prop Drilling:** Сигнал может пробивать любую глубину вложенности.
3. **Много слушателей:** На один сигнал от одной кнопки можно повесить 10 разных функций от 10 разных независимых окон, и все они сработают одновременно.

## А что насчет Redux или React Context?
Если приложение становится огромным (много окон, панелей, вкладок), передавать сигналы от соседа к соседу становится неудобно. 

В React мы используем глобальный стейт (Redux, Zustand, Context).
В PyQt для этого создают паттерн **Event Bus (Шина событий)**. 

Это просто отдельный пустой класс, в котором лежат только Сигналы:
```python
# global_events.py
class EventBus(QObject):
    data_loaded = pyqtSignal(list)
    user_logged_in = pyqtSignal(str)

bus = EventBus() # Глобальный объект
```
Тогда любой виджет из любой точки приложения может импортировать `bus` и крикнуть:
`bus.user_logged_in.emit("Ivan")`

А любое другое окно может слушать:
`bus.user_logged_in.connect(show_welcome_screen)`

### Резюме
React заставляет вас думать **сверху вниз** (данные текут вниз, события всплывают вверх через коллбеки).
PyQt позволяет компонентам быть **полностью изолированными модулями**, которые общаются через невидимые радиоволны (сигналы). Это делает архитектуру десктопных приложений очень надежной.
