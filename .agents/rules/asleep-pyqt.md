# Железные правила архитектуры asleep-pyqt

0. **Строгий лимит и табу на повторное чтение файлов (Zero Redundant Reads)**
   - Запрещено читать более 20 фрагментов кода за один запрос (каждый вызов view_file — это отдельное чтение).
   - Строгий запрет на повторное чтение одних и тех же строк/файлов в рамках диалога. Вся прочитанная информация должна удерживаться в контексте.
   - Если информации не хватает — либо сразу запрашивать у пользователя, либо сразу писать код.
   - Никаких мнимых фиксов по 1 строке с бесконечным перечитыванием. Решения должны быть системными, фундаментальными и чистыми.

1. **Системная архитектура: Локальный Монолит**
   - Единый системный процесс Python (`web.py`).
   - Запуск строго нативно: `uv run .\web.py`.
   - Стиль Qt Quick строго: `os.environ["QT_QUICK_CONTROLS_STYLE"] = "Basic"`.

2. **Архитектура кода: Feature-based (Модульная)**
   - Код делится по предметным блокам (`editor/`, `sidebar/`, `graph/`, `theme/`), а не глубокими абстрактными слоями.
   - Каждый компонент — автономный чёрный ящик: общается только через входные `property` и выходные `signal`.

3. **Прагматичный баланс QML и JS**
   - Декларативная вёрстка и простое локальное поведение (`onClicked: root.saveRequested()`) остаются прямо в QML.
   - Запрещено плодить громоздкие внешние контроллеры на каждый клик.
   - Внешний JS используется только для сложных вычислений (физика сил графа, парсинг синтаксиса).

4. **Интеграция: Прямой фасад Backend**
   - Один понятный QObject `backend` в Python.
   - Синхронные методы (`@pyqtSlot`) для чтения/записи файлов и конфигов.
   - Сигналы (`pyqtSignal`) для реактивных обновлений от бэкенда.

5. **Конфигурация: Config-First**
   - Запрещён хардкод размеров, отступов, таймингов и цветов.
   - Все параметры объявляются в `config/default/*.json` и читаются через `Theme.*` или `backend.get_*_config()`.

6. **Пошаговый контроль: Feature Matrix**
   - Текущее состояние модулей ведётся в `PROJECT_STATUS.md`.
   - Шаг ➔ проверка ➔ коммит ➔ следующий шаг.


8. **Git Flow и Стабильность Релизов (Release Stability)**
   - Ветка `main` в GitHub — священна и предназначена строго для стабильных, проверенных версий.
   - Текущая разработка, промежуточные шаги и эксперименты ведутся локально (или в ветке `develop`).
   - Запрещено пушить в удалённый `origin/main` сырые промежуточные коммиты.
   - Пуш в `main` выполняется только после полного прохождения тестов (`verify.py`), ручной проверки и явного подтверждения готовности этапа.

10. **Каноническая система синтаксиса (14 единиц)**
    1. Однострочный именованный блок текста: `Имя { текст }`
    2. Многострочный именованный блок текста: `Имя { ... }`
    3. Однострочный безымянный блок текста: отдельная строка текста вне фигурных скобок `{}`
    4. Многострочный безымянный блок текста: последовательность строк или абзацев вне фигурных скобок `{}`
    5. Локальная трансклюзия: `Имя()`
    6. Внешняя трансклюзия: `ИмяФайла.ИмяБлока()`
    7. Вики-ссылки для графа: `[[Имя Файла]]`
    8. Теги: `#тег`
    9. Жирный текст: `**текст**`
    10. Курсив: `*текст*`
    11. Зачёркнутый текст: `~~текст~~`
    12. Маркированные списки: маркеры `-`, `*`, `+`
    13. Нумерованные списки: формат `1.`
    14. Цитаты: строки с маркером `> `

11. **Единый чистый Source Mode (Сухой TXT Редактор)**
    - Строго сухое исходное содержание текста, как в чистом `.txt` блокноте. Все строки документа монолитны, в гаттере отображаются только одинаковые аккуратные точки строк на базовой оси без вертикальных линий блоков и лишних графических украшений.
    - Никакого Live Mode, динамических скрытий синтаксиса или фрагментированных псевдо-блоков. Единый, стабильный монолитный редактор.

12. **Оценка сложности исполнения и адекватность запроса (Sanity & Complexity Check)**
    - Агент обязан критически оценивать сложность задачи ДО написания кода: если предложенное решение влечет за собой глобальную переделку стабильно работающего ядра ради косметической мелочи — агент ОБЯЗАН предупредить о рисках, остановиться и предложить минимальное точечное решение.
    - Запрещено слепо перекраивать архитектуру, создавать круговые зависимости и плодить каскадные изменения при мелких багфиксах.
    - Принцип KISS (Keep It Simple, Stupid): если задачу можно решить локальным фиксом внутри одного компонента без переписывания базовых контейнеров — выбирается строго локальный фикс.

13. **Статистика изменений кода (Diff Stats Reporting)**
    - В каждом отчете о внесенных изменениях агент ОБЯЗАН приводить точное количество добавленных (+) и удаленных (-) строк кода, а также созданных и удаленных файлов (на основе git diff / git status).

14. **Разделение движения: вкладка двигает вкладку, холст двигает холст**
    - Вкладка/панель может перемещать строго только саму себя (`panel.x`, `panel.y`).
    - Перемещение вкладки/панели НИКОГДА не должно двигать холст (`panX`, `panY`) или центрировать камеру автоматически.
    - Холст (`panX`, `panY`) перемещается строго пользователем: панорамирование средней/правой кнопкой мыши по свободному пространству. Никаких чужеродных кнопок тулбара («К активному», «Открыть» и т.п.) — весь интерфейс чистый и управляется только через хоткеи и нативные действия.
