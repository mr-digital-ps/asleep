# Архитектура и руководство по горячим клавишам (HOTKEYS.md)

В данном документе описана архитектура глобальной системы обработки горячих клавиш (хоткеев) в проекте **Asleep Text Editor**, причины прошлых сбоев и строгий регламент добавления или изменения комбинаций клавиш, гарантирующий стабильность работы приложения.

---

## 1. Архитектура Global Hotkey Pipeline

Вся обработка горячих клавиш в приложении централизована в виде строгого однонаправленного пайплайна (Single Source of Truth):

```
┌─────────────────────────────────────────────────────────────────┐
│ Физическое нажатие клавиши на клавиатуре (EN / RU раскладка)   │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ QCoreApplication (Python)                                       │
│   └── GlobalHotkeyFilter.eventFilter                            │
│         └── HotkeyMatcher:                                      │
│               1. nativeScanCode (аппаратный скан-код PS/2)      │
│               2. nativeVirtualKey (Windows Virtual Key)         │
│               3. Qt.Key (Qt Enum / Unicode code point)          │
│               4. event.text() (символы RU / EN)                 │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼ (Если найдено совпадение: event.accept(), return True)
┌─────────────────────────────────────────────────────────────────┐
│ PyQt6 Signal: backend.actionRequested.emit(action_name)         │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ views/web.qml (Connections target: backend)                     │
│   └── onActionRequested(action):                                │
│         Проверка активности окна: Qt.application.activeWindow   │
│         Вызов: root.executeAction(action)                       │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ views/action_dispatcher.js                                      │
│   └── dispatchAction(root, splitLayout, ..., action):           │
│         Вызывает методы контроллера активной панели             │
│         (Pane / Sheet / GraphView / HierarchyView)              │
└─────────────────────────────────────────────────────────────────┘
```

### Преимущества архитектуры:
1. **100% независимость от раскладки**: Обработка на уровне аппаратных `nativeScanCode` означает, что `Alt+T`, `Alt+G`, `Alt+E`, `Ctrl+S`, `Ctrl+W` срабатывают идентично как при английской, так и при русской раскладке клавиатуры.
2. **Неуязвимость к фокусу**: Фильтр `GlobalHotkeyFilter` установлен на уровне экземпляра `QCoreApplication`. Он перехватывает системные комбинации до того, как их могут поглотить или потерять дочерние элементы интерфейса.
3. **Единая точка диспетчеризации**: Все действия описаны в одном файле `views/action_dispatcher.js`.

## 2. Разбор причин: Почему хоткеи раньше переставали работать?

Если вы в будущем столкнетесь с ситуацией, когда «хоткей сработал один раз и перестал», проверьте эти 4 первопричины:

### Причина 1: Нарушение QML Property Binding (Самая коварная ошибка)
- **Что происходило**: В `EditorSheet.qml` свойство `isOutlineMode` было связано с родительской панелью: `isOutlineMode: mainBar.isOutlineMode`. При нажатии Escape в коде выполнялось императивное присваивание: `sheetRoot.isOutlineMode = false`.
- **Последствие**: В QML любое прямое присваивание значения связанному свойству (`property = value`) **навсегда разрушает реактивную связь (binding)**. После этого `mainBar.isOutlineMode` менялся при нажатии `Alt+E`, но дочерний `EditorSheet` об этом уже никогда не узнавал.
- **Правило**: **Никогда не присваивать значения свойствам-привязкам напрямую**. Изменение состояния должно инициироваться только через сигналы наверх владельцу состояния (`sheetRoot.showTextModeRequested()` $\rightarrow$ `mainBar.showTextMode()`).

### Причина 2: Сбой фильтра окон при Live Reload (`win && !win.active`)
- **Что происходило**: В `views/web.qml` стояла проверка: `if (count > 1 && win && !win.active) return`. При горячей перезагрузке QML (Live Reload) старый объект окна удалялся асинхронно через `deleteLater()`, из-за чего `count` временно становился равен 2. При этом новое окно в момент инициализации могло иметь `win.active == false`.
- **Последствие**: Сигнал `actionRequested` молча блокировался и выбрасывался.
- **Решение**: Проверка заменена на `if (count > 1 && win && Qt.application.activeWindow && win !== Qt.application.activeWindow) return`. Если в приложении открыто только одно окно, событие выполняется безусловно и никогда не теряется.

### Причина 3: Перехват символов печати в редактируемых блоках
- **Что происходило**: Внутри карточек Live Document находился `TextArea` с директивой `Keys.forwardTo: [outlinerRoot]`. Когда пользователь начинал вводить текст, буквы 'e', 't', 'g' пересылались в `outlinerRoot.Keys.onPressed`, который расценивал их как команды переключения экранов.
- **Последствие**: Пользователь пытался ввести текст заметки, и при первом же нажатии буквы 'е' или 't' приложение выбрасывало его из Live-режима.
- **Правило**: Не устанавливать `Keys.forwardTo` на редактируемые поля ввода (`TextArea`, `TextInput`). Нажатия обычных букв внутри поля ввода — это текст, а не навигация.

### Причина 4: Отсутствие действия в `hotkeys.json`
- **Что происходило**: Действие `show_text_mode` (`Alt+T`) не было прописано в конфигурации `config/default/hotkeys.json`, поэтому `GlobalHotkeyFilter` не знал о нем и не перехватывал его на системном уровне.

### Причина 5: Разрушение привязки `isGraphMode` в `MainBar.qml`
- **Что происходило**: В `MainBar.qml` функция `showTextMode()` выполняла императивное присваивание `mainBar.isGraphMode = false`. Свойство `isGraphMode` в `MainBar` было связано с `EditorSplitLayout.qml`: `isGraphMode: splitLayout.isPrimaryGraphVisible`.
- **Последствие**: При первом же переходе в текстовый режим реактивная связь QML уничтожалась навсегда. После этого при нажатии `Ctrl+G` или `Alt+G` свойство `splitLayout.isPrimaryGraphVisible` переключалось в `true`, но `MainBar.isGraphMode` оставался `false` — граф больше никогда не открывался.
- **Решение**: Заменено на вызов сигнала `mainBar.closeGraphRequested()`. Прямое присвоение убрано, привязка сохраняется навсегда.

### Причина 6: Конфликт русской раскладки `Alt+Г` с `toggle_header` (`Alt+U`)
- **Что происходило**: В русской раскладке буква «Г» (мнемоника для «Граф») расположена на физической клавише `U` (scan 22, VK 0x55). В `hotkey_service.py` для `toggle_local_graph` (`Alt+G`) не был прописан скан-код 22. При этом для действия `toggle_header` была назначена комбинация `Alt+U`.
- **Последствие**: Нажатие `Alt+Г` в русской раскладке перехватывалось как `toggle_header` (скрытие/показ шапки), а граф не открывался.
- **Решение**: Добавлены скан-код 22 и мнемоника «Г» в `toggle_local_graph`, а из `toggle_header` удалена конфликтующая комбинация `Alt+U` (оставлен системный `Ctrl+Shift+U`).

## 3. Регламент добавления нового хоткея (Чеклист)

Чтобы добавить новую горячую клавишу и гарантировать, что она не сломается в будущем:

### Шаг 1. Конфигурация в JSON
Добавьте действие в `config/default/hotkeys.json` (и при необходимости в `config/user/hotkeys.json`):
```json
"my_action": {
  "keys": ["Alt+K", "Ctrl+Shift+K"],
  "description": "Описание действия для интерфейса и справки"
}
```

### Шаг 2. Проверка маппинга клавиш в Python
Убедитесь, что в `services/key_mapper.py` присутствуют скан-коды и буквы для этой клавиши. Если для действия требуется специальная поддержка мнемоник (например, русская 'Г' на клавише U для "Граф"), добавьте правило в `HotkeyMatcher._compile()` в `services/hotkey_service.py`.

### Шаг 3. Обработка в диспетчере действий
В `views/action_dispatcher.js` добавьте ветку в `switch (action)`:
```javascript
case "my_action":
    if (splitLayout && splitLayout.primaryBar) {
        splitLayout.primaryBar.doSomething()
    }
    break
```

### Шаг 4. Управление состоянием только через сигналы
Если действие изменяет режим отображения:
- Флаги состояния (`isOutlineMode`, `isGraphMode`) хранятся в `MainBar.qml`.
- Дочерние компоненты (`EditorSheet.qml`, `DocumentOutliner.qml`) принимают их как свойства `property bool`.
- Для изменения режима дочерний компонент **всегда шлет сигнал**:
  ```qml
  signal showTextModeRequested()
  ```
  а родитель вызывает функцию:
  ```qml
  onShowTextModeRequested: mainBar.showTextMode()
  ```

## 4. Карта режимов и горячих клавиш (согласно ARCHITECTURE.md)

| Категория | Хоткей | Описание действия |
| :--- | :--- | :--- |
| **Режимы листа (Sheet)** | `Alt + 1` | **Source View**: Текстовый редактор со скобочными блоками `{ ... }`. |
| | `Alt + 2` | **Hierarchy View**: Блочный режим карточек без лишнего шума. |
| | `Alt + 3` | **Graph View**: Интерактивный 2D-граф связей файлов `[[...]]`. |
| **Навигация по холсту (Canvas)** | `Alt + ←` / `Alt + →` | Перенос фокуса на блокнот слева / справа. |
| | `Alt + ↑` / `Alt + ↓` | Перенос фокуса на блокнот сверху / снизу. |
| | `Ctrl + \` | Разделение экрана (сплит блокнотов). |
| **Управление поясами (Bands)** | `Alt + F` | Поиск в шапке (Header Search / Command Palette). |
| | `Alt + H` | Таймлайн истории изменений в футере (Footer History). |
| | `Alt + P` | Закрепление шапки / футера (Pin Sticky Header/Footer). |
| **Файлы и вкладки (System)** | `Ctrl + S` | Сохранение текущего документа на диск. |
| | `Ctrl + N` | Создание новой заметки. |
| | `Ctrl + O` | Открытие файла через проводник. |
| | `Ctrl + W` | Закрытие текущей вкладки. |
| | `Ctrl + D` | Открепление текущего блокнота в отдельное окно ОС. |

> [!NOTE]
> **Принцип разделения ответственности клавиш-модификаторов**:
> - **Модификатор `Alt`** зарезервирован исключительно под глобальную макро-навигацию (смена представлений `1/2/3`, переключение блокнотов стрелками, активация поясов `F/H/P`).
> - **Модификатор `Ctrl`** оставлен для системных файловых операций и микро-навигации по словам внутри текстового редактора.
> - Обычные стрелки `↑ ↓ ← →` (без модификаторов) управляют текстовым курсором или выбором активной карточки.
